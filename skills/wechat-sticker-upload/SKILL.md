# 微信表情包专辑上传准备

产出可送审的上传文件夹即可；不要代替用户提交专辑，也不要替用户主张版权。

## 适用范围

只处理表情包**专辑**，不处理单张聊天表情。先确认用户要静态还是动态表情，两者不可混用。用户未提出动态需求时，默认只做静态 PNG。

在生成或导出素材之前，先读[上传规格](references/upload-spec.md)。用户需要当前平台规则时，先核实官方最新说明或上传页；该参考文件只是生产基线，不能作为审核通过的依据。

## 工作流程

1. 盘点现有表情：数量、格式、尺寸、透明通道、文件体积、已有命名。不得覆盖用户原文件。
2. 从用户已认可的图里确定风格基准图，比对轮廓比例、画面留白、线条粗细、眼/面部语言、配色和背景。只重新生成或修改用户授权的偏离素材。
3. 排布顺序：高频反应优先，其次情境反应。按顺序导出编号副本 `stickers/01_<含义>.png` 直到目标数量；16 张装时编号保持 01–16 连续。
4. 在独立输出目录中生成上传素材：主表情、`banner.png`、`cover.png`、`icon.png`、`上传清单.md`。用户未要求时不要打包 ZIP。
5. 起草基础信息，不要编造。给出专辑名称与专辑简介建议；版权方/权利归属一律留作用户填写项，除非用户已提供。
6. 为每张编号表情补一条简短、可编辑的含义。顺序表与文件名顺序必须一致。
7. 校验最终尺寸、PNG/JPG/GIF 格式、体积上限、透明通道要求、横幅不透明度、编号数量。报告输出目录以及需要用户自行补充的内容。

## 视觉一致性卡点

在判定专辑可用之前，必须把所有表情放在一起整体查看。出现身形宽高、线条粗细、五官几何、留白、背景或配色上的明显差异时要指出。以用户认可的基准图为准，重生成时保持其比例。不得仅因为每个文件像素尺寸相同就声称风格一致。

## 元数据与归属

- 专辑名称：给出简短且有区分的标题；不要使用未经核实的商标或他人角色名。
- 专辑简介：一句话描述角色与情绪覆盖范围。
- 版权方/权利归属：只使用用户提供的信息，否则标记为 `待填写`。
- 表情含义：给出可编辑的中文标签，便于上传操作人员判断每张表情的使用场景。
- 清单与图片素材分开保存；除用户明确要求文字类画面且平台允许外，不要把元数据文字画到横幅、封面、图标或表情上。

## 输出结构

```text
<输出目录>/
├── banner.png
├── cover.png
├── icon.png
├── 上传清单.md
└── stickers/
    ├── 01_<含义>.png
    └── ...
```

## 常见错误

| 错误 | 处理要求 |
| --- | --- |
| 后续生成的角色变高、变瘦或取景不一致 | 对照已认可的基准图比对，导出前重生成偏离的素材。 |
| 角色素材带白底 | 表情、封面、图标都必须真实透明；不要把看图工具的马赛克/黑底预览误判为文件背景。 |
| 横幅白底或透明 | 横幅必须不透明，并与微信浅色界面有视觉区分。 |
| 文件名未编号或只有语义名 | 导出带编号的副本，并在旁边记录对应含义。 |
| 版权方未知 | 留给用户填写；不要推断或代拟权利声明。 |
| 单个文件超限 | 非破坏性地缩放或优化，然后重新核对字节数与画面清晰度。 |
